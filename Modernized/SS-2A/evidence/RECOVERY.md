# SS-2A initial recovery

Target `ss-2a(64).exe`, SHA-256 `31b10c65b0f06e9d8e9c4c46e3236759842b2613af5166e3c6a68fb8b5ca9b0b`; x86 PE32. REA/Hopper evidence is retained in `rea-evidence.json` and `analysis-snapshot.json`; Xcode llvm-objdump output is in `native-disassembly.txt`.

The executable identifies itself as SS-2 inlet quantity and bar-list software, version 6.0, October 10, 2011. Its embedded prompts request project metadata, station, roadway side, length 5/10/15 feet, width, height, concrete-pavement choice, and a number of circular or arch openings. It reports concrete, reinforcing steel, deductions, bar lists and project totals; the maximum presented is 50 inlets. These are observed binary strings, not verified runtime coverage.

REA associates the width prompt at 0x493534 with code reference 0x40c32f (Evidence `ev_c693a5e0837ed3195615d1bfbc0230b7c7992edfdb5906b69afe32151895d7e4`), in procedure `sub_408c37`. The calculation-area procedure `sub_40e8f0` has a large Hopper pseudocode record (`ev_533203ae65dda2f53535cbd06d858c668b4d03c71c6bfe46dfcd75e209d13eab`) but contains x87 instructions and unresolved array expressions; pseudocode alone is not a complete or validated formula reconstruction. Calculation logic, opening deductions, pavement and length branches, and bar schedule remain unresolved. The original executable was launched in an isolated Windows folder. Synthetic project, station, side, dimensions, and pavement inputs reached its pipe-opening selection screen (see start.png and inputs.png). The automated key sequence did not advance beyond that screen, so no output or calculation comparison was obtained. The process and temporary scheduled task were stopped; no report was saved.

The SS-2 workflow can plausibly share project metadata, inlet schedule, and report with SS-3/SS-4, but it requires a distinct calculation engine and input fields. Existing saved SS-3 project files must continue to open. Do not add SS-2 quantities to the existing app until its calculations and reports are recovered and verified against the original.

## Windows selector and first observed result

The selector accepts Page Up when its key event is posted to the window from the interactive probe with the extended-key flag. Roadway side and pavement choices consume a single key without Enter; sending Enter after these answers shifted subsequent inputs. A corrected synthetic case entered station 10000, left side, length 5 ft, width 4 ft, height 4 ft, no concrete pavement, and one 15-inch circular opening. The original screen showed 2.614 yd³ concrete and 219 lb steel (caseok2.png). This is one screen-rounded observation, not proof of the calculation equations, bar schedules, other sizes, pavement branches, or numeric identity. No report was written. The probe task and process were removed after capture.
